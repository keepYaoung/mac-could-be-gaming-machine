## 2. 핵심 조정 — "프리픽스 델타"가 아니라 "엔진 델타"일 가능성

두 관점을 화해시키는 열쇠는 **델타가 어디에 있느냐**다.

- CrossOver 23+가 RGL을 고친 것은 대부분 **Wine 소스(WineCX) 패치** —
  CEF 샌드박스가 건드리는 ntdll/스레드/네임스페이스 동작을 고친 것.
  이건 **보틀(프리픽스) 안의 설정이 아니라 Wine 바이너리 자체**에 들어있다.
- 그래서 STEP 3의 프리픽스 diff(폰트/레지스트리/런타임)로는
  **CEF 픽스가 안 잡힐 수 있다.** ← 이게 어제 "천장"이라고 부른 이유.
- **그러나** Sikarugir 엔진(`WS12WineSikarugir`)은 **WineCX 소스 계보**이고,
  CX 패치는 **시차를 두고 무료 엔진에 유입**된다(배경 §1). 즉 프리픽스에서
  못 만지는 것을 **엔진 버전에서는 만질 수 있다.**

**결론:** ⑤는 "영원한 천장"이 아니라 "**엔진 버전에 종속된 벽**"일 개연성이 높다.
따라서 answer-key 역산은 프리픽스뿐 아니라 **엔진/Wine 버전까지 반드시 포함**해야 한다.

### 그래서 우선순위가 바뀐다 (최고 레버부터)

1. **엔진 버전 정면돌파 (최우선, 비용 최소).**
   현재 Sikarugir 엔진 버전 확인 → **최신 `WS12WineSikarugir` (10.0_6+ 이상)** 로
   교체 후 RGL 재기동. CX CEF 패치가 이미 유입됐다면 ⑤가 그냥 사라질 수 있다.
   프리픽스 diff 노가다보다 이게 먼저다.
2. **CX 보틀의 Wine 버전 문자열 확보.** CX가 몇 세대에서 고쳤는지 알면,
   Sikarugir 엔진이 그 시점 이후 소스를 담고 있는지 판정 가능.
3. **그 다음에** 프리픽스 델타(폰트/레지스트리/런타임) diff — ①~④ 재발 방지 및
   부차 요인 제거용. (핸드오프 STEP 3)

## 3. ①~④ 재발 방지 체크리스트 (이미 뚫은 벽, 유지사항)

새 프리픽스/엔진 교체 시 아래가 리셋될 수 있으니 재확인:

- **② Error 1002:** `drive_c/users/<user>/Documents/Rockstar Games/{Social Club,
  Red Dead Redemption 2/Settings}` 트리 존재 확인. (어제 영구 수정, 유지)
- **③ CEF init 플래그:** `--no-sandbox --disable-gpu --in-process-gpu
  --disable-gpu-compositing` 로 "Connecting to Rockstar Games Services" 스플래시까지 도달.
- **① D3DMetal:** 런처 단계 OFF.

## 4. 판정 기준 (이 벽이 진짜 천장인지 최종 확인)

- 최신 엔진 + CX diff 이식을 **다 했는데도** `libcef+0x…: int3`가 **같은 자리**에서
  재현 → 그때는 어제 결론(free-Wine 천장, CX 독점 패치 미유입)이 확정.
- 최신 엔진에서 ⑤가 사라지거나 크래시 주소/양상이 바뀜 → **엔진 델타가 원인**이었음.
  → 프로파일 DB에 "요구 엔진 최소버전"을 확정 기록.
